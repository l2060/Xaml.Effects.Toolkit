# GameResource.Package 磁盘格式 2

这是独立格式。容器结构中的所有整数以小端序列化（Meta 内部遵循 MessagePack 字节序），偏移和长度使用非负 Int64，不直接保存 C# 结构体内存。

## 文件头

偏移 0 和 4096 各有一个 4096 字节文件头。数据分配从偏移 8192 开始，分配单位为 8 字节。以下偏移相对单个文件头：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | ASCII GRPKG002 |
| 8 | 4 | 格式版本 2 |
| 12 | 4 | 标志：0=明文，1=加密 |
| 16 | 8 | 保存序号，从 1 开始 |
| 24 | 8 | 当前索引记录的物理位置 |
| 32 | 8 | 索引实际存储长度 |
| 40 | 8 | 索引解码后的长度 |
| 48 | 8 | 提交时的逻辑文件长度 |
| 56 | 16 | PBKDF2 随机盐 |
| 72 | 4 | PBKDF2-SHA256 次数；明文为 0 |
| 76 | 4 | 保留 |
| 80 | 32 | 解码后完整索引的 SHA-256 |
| 112 | 8 | 索引分配空间长度 |
| 120 | 8 | 保留 |
| 128 | 32 | 加密包：前 128 字节的 HMAC-SHA256；明文为零 |
| 160 | 32 | 前 160 字节的 SHA-256 |
| 192 | 3904 | 保留 |

加密密钥为 PBKDF2-SHA256 输出的 32 字节，默认 600000 次，当前实现接受 100000–10000000 次。文件头的密码派生与认证仅在打开时执行。

普通索引采用原始连续字节；加密索引采用下述分块格式，编码类型固定为 None。

## 解码后的索引

布局：

~~~text
24 字节索引头
64 字节 × 记录数
UTF-8 完整路径区
16 字节 × 空闲区数量
~~~

索引头：ASCII GRINDEX2（8 字节），记录数 Int32，路径区字节数 Int32，空闲区数量 Int32，保留 Int32。

记录按完整路径的 UTF-8 字节序严格递增。没有重复键，不做大小写折叠或 Unicode 归一化。路径区只保存记录的完整路径，不保存字符串结束符。

每条记录：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | 路径在名称区内的偏移 |
| 4 | 4 | 路径 UTF-8 字节数 |
| 8 | 1 | 0=文件，1=空目录 |
| 9 | 1 | 0=原始连续数据，1=分块数据 |
| 10 | 1 | 写入策略：0=None，1=Auto |
| 11 | 1 | 保留 |
| 12 | 4 | MessagePack Meta 字节数 |
| 16 | 8 | 文件数据的物理偏移 |
| 24 | 8 | 实际存储长度 |
| 32 | 8 | 原始内容长度 |
| 40 | 8 | Meta 数据记录的物理偏移；无 Meta 为 0 |
| 48 | 8 | 原始内容的 XXH64，seed=0，数值按小端保存 |
| 56 | 8 | 文件数据的分配长度 |

空文件不分配数据空间，偏移和存储/分配长度均为零，内容校验值是空字节序列的 XXH64。空目录只使用名称及记录类型，其他字段均为零。

空目录标记和文件都不能有后代路径。目录前缀按完整路径加 / 匹配，父目录由路径推导。

每条空闲区是 Int64 偏移和 Int64 长度，按偏移排列，不能重叠，相邻空闲区必须合并。有效文件分配区、Meta 分配区、索引分配区和空闲区应恰好覆盖 [8192, 提交长度)，不能重叠或存在未跟踪区间。

## 独立 Meta 记录

Meta 不属于索引，不计入索引 SHA-256。索引精确长度为 `24 + 64 × 记录数 + 路径字节数 + 16 × 空闲区数`，打开时不读取 Meta 字节。

Meta 记录解码后为 `8 字节小端 XXH64(MessagePack 字节，seed=0) + MessagePack map`。map 的键必须是字符串，长度最多 1 MiB，最大对象嵌套深度 64；不存储 .NET 类型名。标量、数组、嵌套 map、二进制和扩展类型遵循 MessagePack 规范。

Meta 不压缩。明文直接存储上述字节；加密时使用下述 64 KiB 分块布局，编码为 None，上下文为 3。索引中的 Meta 长度不包括 8 字节校验值。令 `R = MetaLength + 8`，块数 `N = ceil(R / 65536)`：明文存储长度是 R，加密存储长度是 `R + N × 44`；分配长度向上取整到 8 的倍数，因此无需额外记录长度字段。

无 Meta 时长度和偏移均为零；空 map 的 MessagePack 长度为 1，属于存在的 Meta。空内容文件可以有独立 Meta。目录标记不能有 Meta。

读取 Meta 时才验证其 XXH64/加密认证和对象格式；Verify 强制读取验证所有 Meta。更新 Meta 仅替换这段空间并更新索引；更新内容可保留同一 Meta 偏移。旧 Meta 和文件内容遵守相同的提交后空间复用规则。
## 分块数据

块原始大小 65536 字节，最后一个块由文件原始长度确定。零长度记录没有块。块数为 ceil(原始长度 / 65536)。

布局：

~~~text
16 字节 × 块数的块描述表
连续的块 0、块 1、……
~~~

每个块描述：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | 块相对当前数据记录起点的偏移 |
| 8 | 4 | 块存储字节数，包含加密开销 |
| 12 | 1 | 实际编码：0=None，1=LZ4 原始块 |
| 13 | 3 | 保留，零 |

压缩仅在 LZ4 输出小于原始块时采用。所有块形成连续布局。读取验证描述范围、相邻块位置以及解码长度。

明文块直接保存编码后字节。加密块保存：

~~~text
12 字节随机 nonce | 16 字节 GCM tag | 密文
~~~

每个块使用 AES-256-GCM，AAD 共 32 字节：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | 数据记录的物理起始偏移 |
| 8 | 8 | 块序号 |
| 16 | 4 | 该块的原始长度 |
| 20 | 4 | 编码后明文长度，不含 nonce/tag |
| 24 | 1 | 实际编码 |
| 25 | 1 | 上下文：1=资源内容，2=目录索引，3=Meta |
| 26 | 6 | 零 |

绑定位置和块序号可以检测块错置；修改路径不需重加密，移动物理数据则需要重新加密。每次加密生成新的随机 nonce，不能从可复用的物理位置推导 nonce。

## 保存及空间重用

1. 从当前可用空闲区或文件尾分配新内容和 Meta；不覆盖当前提交仍引用的区域。
2. 替换和删除的旧内容和 Meta暂存于本次编辑的待释放列表。
3. 分配并写入新索引。新空闲列表包含待释放内容和旧索引，但尚不能用于后续分配。
4. 持久化刷新数据与新索引。
5. 写入一个带有更高保存序号的文件头并持久化刷新。
6. 写入另一个相同的文件头并持久化刷新。
7. 发布新的内存索引与空闲列表。此后才能重用刚释放的空间。

如果逻辑尾部缩短，实际截断必须在两个新文件头持久化之后进行。发布前保留旧提交的物理长度，使旧文件头仍可恢复。

恢复时验证两个头部及其索引，从有效候选中选择最高保存序号。以编辑方式打开时，先将选定头部持久化到两个位置，再截去未提交尾部；随后才能分配空闲空间。只读打开不会修复或写入文件。

无独立日志文件，无历史版本接口，无并发快照读取。
